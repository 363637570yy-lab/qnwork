## 1. 产品定义

**QNwork** 是给造价、机电、投标人员使用的本机工程工作台。用户选定招标包目录、选择任务，得到可复核的 Word / Excel。窗口标题、关于页、开始菜单与桌面快捷方式一律显示 **QNwork**，不再显示 Grok / Grok App。

- 对话与分析：由本机 Grok Build CLI 完成。
- 数量、清单、功率：由定向脚本计算，不由模型估算。
- 壳不内嵌模型，不自研对话循环，不内嵌算量 / 组价算法。

### 1.1 第一版必须完成的闭环

打开「新汇园 89 号楼」招标包 → 一键出表 → 输出内部报价清单与广联达导入表 → 窗口列出文件路径与待确认项。

v0.1 **只保证这一包**。数量与现有 `.analysis` 脚本产出的表格一致，不宣称换一个招标包也能算。

### 1.2 冻结原则

| 原则 | 执行 |
| --- | --- |
| 资料只读 | 业主 / 设计院招标包不写回。产物只写平级 `DXF/<项目名>/` |
| 数出脚本 | 点位、延长米、金额公式由 Python 计算。模型只写特征、说明、答疑表述 |
| MCP 是能力 | 凡能出数、出文件的能力，先做成 MCP 工具。安装包带上，进程外执行，不编译进壳 |
| Skill 是流程 | `SKILL.md` 只写何时调、先调谁、什么不能编。禁止 Skill 再直接 `python xx.py` |
| 任务目录是入口 | 侧栏按钮来自任务目录，不写死。新任务加一行目录，不改 App 业务 |
| 工具共用 | 侧栏与对话调用同一 MCP，禁止两套出数逻辑 |
| 一键直调 | 出数 / 出表任务：壳按目录直调 MCP，再把摘要贴回会话。禁止只丢一句 prompt |
| 先适配 | 包装现有脚本：只加路径参数和统一返回值，不重写算量 / 组价算法 |
| 单引擎先行 | 第一版 sidecar 只接 `grok agent stdio`。换 Claude / Codex 放入后续版本 |
| 不改用户 grok 配置 | 默认 shared 模式不得改写 `~/.grok`。工程 MCP / Skill / 任务目录放项目级 `.grok/` 或独立 `GROK_HOME` |

### 1.3 本期不做

- 不写广联达 GBQ 二进制
- 不做网页版
- 不修改 Grok Build 源码
- 不自研对话循环
- 不做全专业 BIM
- 不把 Computer Use 接到 CAD / 广联达软件上点鼠标
- 不把 v0.1 做成通用算量引擎（换设计院、换图层规则是后续）
- 不把图框 atlas、效果图（`cad-to-viz`）打进第一版
- 不维护上游 Grok App 的 Remote IM、皮肤包、ChatCut、15 语言跟齐
- 不把领域算法写成壳内「原生连接器」

## 2. 架构

### 2.1 集成方向（后续只按此加能力）

对照 WorkBuddy：Skill 管流程，MCP 管连接，壳不管领域算法。工程工作台沿用这一分层，并多一条——涉及数量和出表的入口必须直调 MCP。

```
工程工作台（壳）
  ├─ 对话：Skill 教模型调 MCP
  ├─ 工程任务：读任务目录，直调 MCP
  └─ 成果面板：只渲染 MCP 返回的 files[] / open_items[] / error
        │
        ▼
eng-tools（MCP 进程，安装包带上，不进 App 进程）
  eng.takeoff · eng.quote · eng.glodon
  以后按同一契约加：eng.index · eng.rfi · eng.org · eng.atlas · …
```

| 层 | 职责 | 加新能力时动这里 |
| --- | --- | --- |
| 壳 | 选招标包、会话、权限、更新、渲染任务目录与成果 | 几乎不动 |
| 任务目录 | 显示名、调哪些工具、顺不顺序、直调还是只走对话 | 加一行 |
| Skill | 教对话何时调、失败怎么办、数字纪律 | 加一个 `SKILL.md` |
| MCP | 真出数、真出文件。统一入参 / 出参 | 加一个 tool（或一个 server） |

禁止出现的分叉：

- Skill 里再调散落脚本，按钮走 MCP（两套逻辑）
- 为某个工具在壳里重写 ezdxf / 组价 / Word
- 侧栏写死按钮，每加一个任务就改一版 UI 业务

### 2.2 任务目录

侧栏不维护一份硬编码菜单。目录随 `eng-tools` 分发（例如 `.grok/eng-tasks.json`），壳只渲染和执行。

一条任务至少包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定标识，发布后不改语义 |
| `label` | 侧栏显示名 |
| `group` | 分组，如「机电投标」 |
| `tools[]` | 按顺序调用的 MCP 工具名 |
| `skill` | 对应 Skill 名。对话触发时用；直调完成后把摘要按该 Skill 的口径贴回 |
| `invoke` | `direct`（壳直调 MCP）或 `chat`（只注入 Skill，交给模型） |

规则：

- 出数、出表、出可交付文件：必须 `invoke: direct`
- 纯分析、措辞、解释：可以 `chat`
- 功率表在内部清单 xlsx 内，不单列一条出数任务

v0.1 目录：

| id | label | tools | invoke |
| --- | --- | --- | --- |
| `takeoff-quote-glodon` | 算量并出表 | `eng.takeoff` → `eng.quote` → `eng.glodon` | `direct` |
| `quote-only` | 内部清单 | `eng.quote` | `direct` |
| `glodon-only` | 广联达表 | `eng.glodon` | `direct` |

v0.2 只加两行：`rfi`、`org`，仍是 `direct`。图框、效果图、信息价以后同样加行，不改壳。

点击 `direct` 任务 = 壳按 `tools[]` 顺序调 MCP → 成果面板更新 → 摘要和 `open_items` 贴进当前会话。不另开后台队列。进度显示工具状态，不以模型口播为准。

### 2.3 三层运行时

| 层 | 定案 |
| --- | --- |
| 壳 | 从 Grok App 改。保留项目夹、会话、Ask / YOLO、更新通道。更换名称、图标、默认工作区；增加按目录渲染的任务侧栏与成果面板。新 UI 放独立模块，不往 `App.tsx` / `AppWorkbench.tsx` 堆功能 |
| 核 | 本机已安装并登录的 Grok Build CLI。推理、改文件、权限、对话里的 MCP 由该 CLI 执行 |
| 工具 | `eng-tools` 独立进程。随安装包分发 Python 环境与脚本。对话经 ACP 注入同一 server；按钮直连同一 server |

### 2.4 仓库划分

| 位置 | 内容 |
| --- | --- |
| 本仓库（桌面壳） | 当前工作区根目录即壳源码（原 grok-app 树）。品牌、任务侧栏、成果面板。侧栏只消费任务目录，不内嵌工具实现 |
| `eng-tools`（待建） | MCP 服务器、任务目录、Skill、适配层、从新汇园收口的脚本、复用已有 skill 的索引/布局 |
| 招标包（外部） | 只读。不进 git，不写生成物 |

实施顺序：先 `eng-tools` 在命令行复现新汇园两张表，再改壳按目录做一键按钮。不要先换皮。

### 2.5 三个根目录

实际不是「打开一个文件夹」就齐了，是三棵树：

| 树 | 例 | 权限 |
| --- | --- | --- |
| 招标包 | `D:\BCKF\CAD\新汇园89号楼超级创业者社区场景验证测试平台二期工程` | 只读。会话 cwd / 信任目录 |
| DXF 工作区 | `D:\BCKF\CAD\DXF\新汇园89号楼超级创业者社区场景验证测试平台二期工程` | 可写。`output_root` |
| 原始 CAD 对照 | 招标包内 DWG / PDF | 只读。takeoff 仍会读指定 PDF；索引阶段才转 DXF |

打开工作台时信任招标包。`output_root` 用已有 `layout.py` 推到**平级** `DXF/<项目名>`，并给这条路径写权限。禁止把产物写进招标包，也禁止把会话 cwd 设成 `DXF/` 却假装招标包是项目根。

### 2.6 配置落点

| 范围 | 路径 |
| --- | --- |
| 用户级 MCP | 不写。避免改用户已有 `~/.grok/config.toml` |
| 工程 MCP / Skill / 任务目录 | 随 `eng-tools` 分发；壳用独立 `GROK_HOME` 或项目级 `.grok/` 加载 |
| 会话注入 | 对话：Extensions Hub / 项目配置把 MCP 注入 ACP `session/new` \| `session/load` |
| 一键路径 | 壳按任务目录直连同一 MCP，不经过模型 |
| Skill 格式 | 标准 `SKILL.md`（与 Grok Build 一致） |

### 2.7 运行时数据

Grok App 原有 app-data 机制保留：`projects.json`、`sessions`、`automations`、`settings`、`secrets`。

工程产物不写入 app-data，只写入：

- `DXF/<项目名>/AI生成资料/`（可交付成品）
- `DXF/<项目名>/.analysis/`（底稿、索引、日志）

安装包 identifier、app-data 目录、AUMID 与用户已安装的 Grok / Grok App 分离，互不抢任务栏与配置。

### 2.8 以后怎么加能力

| 要加的东西 | 改 MCP | 改 Skill | 改任务目录 | 改壳 |
| --- | --- | --- | --- | --- |
| 新汇园出表 | v0.1 三个 tool | 机电算量出表 | 三行 | 否 |
| 答疑 / 施组 | 两个 tool | 两条 | 两行 | 否 |
| 缺索引先建库 | `eng.index` 包现有 `index_drawings` | 可选 | 一行（`direct`） | 否 |
| 图框底图 / 效果图 | 新 tool，包 atlas / viz | 一条 | 一行或一个分组 | 否 |
| 信息价、规范检索 | 新 tool | 视需要 | 视需要 | 否 |
| 只改对话说法 | 否 | 是 | 否 | 否 |

判断口诀：能出文件或出数 → 先 MCP；只要教模型怎么用 → 只改 Skill；要出现在侧栏 → 加目录行；不要改壳。

## 3. 定向工具

### 3.1 现状（必须写进方案，避免实施时按「已有管道」理解）

对照 `D:\BCKF\CAD\DXF\新汇园89号楼超级创业者社区场景验证测试平台二期工程\.analysis\`：

| 事实 | 含义 |
| --- | --- |
| `takeoff_qty.py` 读 `index.json`，写 `takeoff_qty.txt` | 抽点位 / 文字 / 图层延长米，不吐清单行 |
| `build_quote.py` / `build_glodon.py` 数量写在 `item()` / `ITEMS` 里 | 人工誊录。它们**不读** takeoff 结果 |
| 路径全部写死本机盘符 | 统一入参要靠适配层，不是脚本已经通用 |
| 没有 `index.json` 则 takeoff 起不来 | 索引来自已有 skill，不是 takeoff 自己建的 |
| `build_rfi.py` / `build_org.py` 是新汇园手写文档 | v0.2 包装后仍是这一包专用，不是「读事实库自动填模板」 |
| CAD 现有三套 Claude 技能 | 读图、图框 atlas、效果图。后两套第一版不接入；接入时仍走 MCP，不写进壳 |

因此：v0.1 验收「与现有脚本产出一致」= **复现已有两张表**，不是「现场重新算出同一套数」。Skill 里「没有 takeoff 不得填数量」是**模型纪律**，从 v0.1 起约束对话；脚本层的 quote / glodon 仍先原样包装。

### 3.2 前置：索引，不另起炉灶

已有技能：`D:\BCKF\CAD\.claude\skills\engineering-project-analysis\`

```
survey → index_drawings → read_office → extract_facts → crosscheck
路径一律走 layout.resolve_paths()
```

`index_drawings.py` 最贵（参考约 48 张图、10 分钟），依赖 LibreDWG。之后各阶段读 `index.json`，不再解析原图。

v0.1 新汇园已有 `index.json`。一键出表**不重新索引**。若缺失：失败并返回原因（提示先跑索引），不写空表。不要在 `eng-tools` 里再写一套索引；日后做成 `eng.index` 时仍包装现有脚本。

`cad-region-atlas`、`cad-to-viz` 留在 CAD 技能目录，不进 v0.1 安装包。

### 3.3 MCP 工具

v0.1 三个，v0.2 补两个。都挂在 `eng-tools` 这一个 server 上，用 `eng.` 前缀：

| 工具名 | 版本 | 作用 | 包装脚本 | 输出 |
| --- | --- | --- | --- | --- |
| `eng.takeoff` | v0.1 | 按图抽取点位、文本、块、延长米 | `takeoff_qty.py`、`recheck_qty.py`、`count_devices.py` | `.analysis` 数量底稿 |
| `eng.quote` | v0.1 | 内部测算清单与功率表 | `build_quote.py` | 清单报价 xlsx |
| `eng.glodon` | v0.1 | 广联达可导入列 | `build_glodon.py` | 广联达表 xlsx |
| `eng.rfi` | v0.2 | 出图纸答疑 | `build_rfi.py` | 答疑 docx |
| `eng.org` | v0.2 | 出施组章节 | `build_org.py` | 施组 docx |

纳入 `eng-tools` 后按工具名收口，不再从项目目录直接调用散落脚本。`docx_kit.py`、`layout.py`、`toolchain.py` 从已有 skill 复用，不复制第二份。

### 3.4 统一契约

适配层实现下列入参 / 出参。以后每个新 tool 遵守同一出参，侧栏和成果面板才不用改。v0.1 脚本本体仍是新汇园规则；`discipline` 先收下，**可以忽略**。

**入参**

| 参数 | 说明 |
| --- | --- |
| `project_root` | 招标包只读根目录 |
| `output_root` | `DXF/<项目名>`，缺省由 `layout.py` 从 `project_root` 推导 |
| `discipline` | `电气` / `智能化` / `给排水` / `消防` / `暖通` / `全部`。v0.1 可忽略 |

**出参**

| 字段 | 说明 |
| --- | --- |
| `ok` | 是否成功 |
| `files[]` | 生成文件的绝对路径 |
| `qty_summary` | 数量摘要（有则填；quote / glodon 可从已有行汇总） |
| `open_items[]` | 待确认项。v0.1 从「估算 / 待确认 / warn」行抽取 |
| `log_path` | 运行日志路径 |
| `error` | `ok=false` 时必填原因 |

失败必须返回原因，禁止静默写空表。

### 3.5 Skill（只给对话用）

一键按钮不靠 Skill 决定调不调。Skill **不得**再写 `python takeoff_qty.py` 这类旁路。

| Skill | 触发 | 动作 |
| --- | --- | --- |
| 机电算量出表 | 用户提到清单、对量、报价、广联达 | 先 `eng.takeoff`，再 `eng.quote` + `eng.glodon`。数字以工具返回为准 |
| 图纸答疑 | 用户提到疑问、RFI、提疑 | 只读事实库与已有产物，禁止编造数量 |
| 施工组织设计 | 用户提到施组 | 按已有生成器出文；数字引用已有 takeoff / 清单，不口头估 |

### 3.6 数字纪律（写入每一个 Skill）

1. 没有 takeoff 或清单工具结果，不得填写工程数量。
2. 管件、支吊架等图纸不可见项必须标暂估，并进入 `open_items`。
3. 信息价必须注明月份与来源，不得写成锁定价。

### 5.2 v0.1 验收步骤

### 7.4 自动更新怎么接到本仓

上游更新有两条路，都要改指向，不能只改界面上的「检查更新」链接。

**A. 签名安装包（正式自动更新）**

发版 CI 编译时注入：

- `GROK_UPDATER_PUBLIC_KEY`
- `GROK_UPDATER_ENDPOINT` = 本仓的 `latest.json` 地址，例如  
  `https://github.com/363637570yy-lab/qnwork/releases/download/qnwork-desktop-latest/latest.json`
- `TAURI_SIGNING_PRIVATE_KEY`（及可选 password）

`src-tauri/build.rs` 看到公钥 + endpoint 才打开 updater 插件。本仓库目前没有 `.github/workflows/`（文档清理时上游 workflow 已不在）。v0.1 要自动更新，必须在本仓补一条 Windows 发版 workflow：打 tag → 编 NSIS → 签名 → 上传安装包和 `latest.json` 到 **本仓** Releases。

密钥只放 GitHub Secrets，不进 git。本地 `tauri dev` 不注入这两项，开发构建不连生产更新接口。

**B. 未签名 / 本机构建（兜底）**

走 `app_update.rs` 查 `releases/latest`，设置里打开浏览器下安装包。仓库改成 `363637570yy-lab/qnwork` 后，这条兜底才不会跳回上游 Grok App。

### 7.6 吸收上游更新

`origin` 永远是本仓。吸收 Grok App 用「fetch + 开分支合并」，不要改远程，不要 rebase 到 `upstream/main` 再强推。

```
git fetch upstream
git checkout -b absorb/upstream-YYYYMMDD
git merge upstream/main
# 解决冲突 → 确认 QNwork 名称与更新地址仍指向本仓
git checkout main
git merge --no-ff absorb/upstream-YYYYMMDD
git push origin main
```

只想拿某一个上游修复时，从 `upstream/main` cherry-pick 那几个 commit。

冲突时下列覆盖层以 QNwork 为准，不要接回 Grok 名或 `RongleCat/grok-app`：

- `src-tauri/tauri.conf.json`、`tauri.windows.conf.json`、`tauri.dev.conf.json`（名称、identifier、`qnwork://`）
- `package.json` 的仓库字段
- `src-tauri/src/app_update.rs`、`src/hooks/useUpdater.ts`
- `zh` / `en` 的 `app.name` 与关于/导览
- 本方案与 `AGENTS.md`
- 发版 workflow 的 Releases / `GROK_UPDATER_ENDPOINT`（必须仍指向本仓）

可以看、默认不跟的上游改动：Remote IM、皮肤包、ChatCut、15 语言跟齐、发版刷贡献者头像、往 `App.tsx` 堆功能。
